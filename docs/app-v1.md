# 本地 App V1

## 启动

在项目目录打开 PowerShell：

```powershell
.\Start-PGOS.ps1
```

启动器依次查找 PGOS_PYTHON 指定的解释器、系统 Python launcher/Python、可用的 Codex 随附 Python。最后一项只是可选兼容入口，不要求安装 Codex。需要 Python 3.10 或更新版本；无可用解释器时安装 Python 后重试。

若 PowerShell 执行策略阻止脚本，可仅对本次进程执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-PGOS.ps1
```

已有 Python 时跨平台启动：

```sh
python -B -m app.server
```

默认使用空闲回环端口。Windows 优先打开 Edge 独立窗口，否则打开默认浏览器。终端会显示本机访问地址。关闭窗口不等于停止服务；用界面「退出应用」或终端 Ctrl+C 停止。

```powershell
.\Start-PGOS.ps1 -Demo
.\Start-PGOS.ps1 -NoBrowser -Port 8765
```

Demo 模式只生成虚构记录到临时工程；正常退出服务后自动清理，不碰真实工作空间。NoBrowser 模式需手动打开终端显示的地址，端口占用时选择另一个端口或省略 Port。

## 一次完整使用

1. 选择「目标、学习、习惯、知识、反思、周复盘」之一，点击「新建记录」。
2. 填写标题、日期，应用复制对应模板到 private/workspace 下的对应目录。
3. 在正文编辑 Markdown；点击保存或 Ctrl+S。创建即落盘，后续编辑需手动保存；离开未保存记录会提示。
4. 重新打开记录，或填写标题/正文关键词，并可组合类型、起止日期和标签，再点击「搜索」或按 Enter。筛选不会在输入时自动运行；点击「清除筛选」恢复列表。结果可直接打开，显示标题、日期、类型和匹配片段。侧栏数字为各类记录总数，不表示目标完成率或能力评价。
5. 反思记录可展开引导字段。字段区是本次新增补充，点击加入正文或保存时追加，不替换已有原文；旧字段内容在 Markdown 正文中编辑。

反思字段为事件、事实（用户自述）、感受、解释（待验证）、反例、下一步及状态。状态需明确选择 Suggested、Decided、Executed 或 Result，程序不根据文本自动推断状态，不自动更新个人记忆。

文件始终是普通 UTF-8 Markdown。可用其他编辑器修改；界面保存前会比较内容版本，发现冲突即拒绝覆盖。保留当前编辑文本后重新打开记录，手动合并再保存。新标题会同步到正文的第一个一级标题，不用于拼接文件路径。

标签筛选兼容旧记录，不改变文件格式。需要标签时，在正文独立一行写 `标签：练习，观察`（英文冒号、逗号也可）；筛选时输入一个标签，大小写和开头的 `#` 不影响匹配。没有该行的旧记录仍可通过关键词、类型和日期检索。搜索只扫描六类记录目录中的 Markdown，不调用 AI 或访问网络；每次最多检查 500 个文件，显示最多 100 个匹配结果。达到扫描上限时界面会提示，结果可能不完整；大型资料库目前没有索引或性能保证。

## 可选本地 AI

普通记录、计数和搜索完全不需要 Ollama。要启用分析，请自行安装 Ollama 和适合设备的本地模型，并关闭 Ollama 云端功能。

Windows 下先退出已有 Ollama 服务，再在单独的 PowerShell 中设置并启动：

```powershell
$env:OLLAMA_NO_CLOUD = '1'
ollama serve
```

App 不下载模型。模型安装方式参考 [Ollama 官方说明](https://docs.ollama.com/quickstart)；禁用云端方式见 [官方 FAQ](https://docs.ollama.com/faq)。使用默认本机端口 11434。

1. 在时间线勾选 1–5 条记录。先保存编辑区的修改。
2. 点击「本地 AI 分析」，展开完整输入，核对记录、正文、日期和系统约束。此时没有发送记录给模型。
3. 点击「检测本机模型」。只查询模型信息，不发送记录。
4. 选一个本地模型，再点击「将上述输入发送给本机模型」。发送的是已经预览的固定快照；不会再读其他记录或悄悄截断正文。
5. 草稿显示后可编辑。勾选确认框并点击确认保存，才写入新的反思文件。原记录保留，来源和助手推断标签不能被模型输出替代。

模型未安装、服务不可用、远端模型或请求失败时显示错误；普通功能继续运行，无云端回退。关闭草稿窗口不会保存草稿；关闭服务后内存草稿丢失。15 分钟后快照过期，需要重新选择。

## 验证与边界

执行回归与公开扫描：

```sh
python -B -m unittest discover -s tests -v
python -B scripts/pgos.py check
```

开发测试只使用临时工程的虚构记录。测试覆盖创建/重开/保存、按需搜索与组合筛选、旧 Markdown、外部编辑冲突、原子写入失败、越界/链接、HTTP 权限、无 Ollama 使用、输入快照、草稿确认和云端模型阻断。实际验收结果见 [验证记录](app-validation.md)。

当前限制：

- 轻量网页壳，不是安装包；没有托盘、自动启动、附件、富文本所见即所得或同步功能。
- 只处理六类目录的 UTF-8 Markdown，单文件上限 256 KiB；主动搜索最多扫描 500 个文件并显示 100 条结果，适合小型个人资料库，没有大型库性能保证。
- AI 一次最多五条、输入上限 24000 字符；本机推理最多等待约 90 秒。模型可能受自身上下文窗口限制，用户应缩小输入范围；程序不保证模型完整使用全部内容或生成事实正确。
- 记录编辑手动保存；AI 草稿仅内存保存。断电或异常退出可能丢失未保存编辑；没有自动备份与恢复功能。
- 同一服务内串行写入及版本冲突检查覆盖常见并发场景，不提供跨进程文件锁；不要同时启动多个服务编辑同一工作区。不能防御有文件权限的恶意本机进程在校验后替换目录。
- Markdown 原文以纯文本展示，不执行 HTML 或自动加载图片、链接预览。
- 删除会把记录移入工作空间回收区，可从应用中恢复；回收区不等同于独立备份。

公开打包使用精确清单工具 `python -B scripts/pgos.py export`。只导出公共源码和文档，不复制 private、旧 Git 历史、浏览器资料或测试临时数据。
