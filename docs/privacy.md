# 隐私边界

## 内容分类

| 内容 | 处理方式 |
| --- | --- |
| 通用方法、空白模板、独立编写的虚构示例 | 审核后加入公开清单 |
| 日记、私人笔记、目标、决定、职业规划、模式和 Agent 记忆 | 保留在 private 内，不进入公开示例 |
| 姓名、学校、专业定位、联系方式、身份号码、本机路径 | 从公共文档去除，按需使用中性占位符 |
| 配置、Token、Cookie、API Key、密钥 | 本地私有配置或外部环境变量，公开仅保留字段说明 |
| 图片、附件、截图和二进制文件 | 默认不导出；人工检查内容和元数据后另设计审核流程 |
| Git 提交、作者、邮件、远端地址、历史文件名 | 单独审核；旧个人仓库默认不可直接公开 |

## 工具能检查什么

`check` 读取精确清单，查常见凭证格式、密钥块、邮件、电话号码、身份号码、绝对路径及身份描述。拒绝遗漏的公共文件、非 UTF-8 内容、符号链接/目录联接和私有目录条目。忽略目录只用于隔离本地数据，不代表其中没有敏感信息。

可将已知敏感词每行一个写入 `private/audit/denylist.txt`，执行 `python scripts/pgos.py check --denylist private/audit/denylist.txt`；导出也支持此选项。列表不得公开。

检查输出只有文件、行号和类别，不输出原值。它不能识别所有真实姓名、间接身份、语义隐私或新型密钥；零发现不等于零风险。不要以公共抑制规则绕过真正敏感的内容。

## 历史与远端

`.gitignore` [不作用于已被跟踪的文件](https://git-scm.com/docs/gitignore)。移动或删除工作区文件、增加一个删除提交，都不会清除旧版本。

用 export 生成无历史副本，在旧仓库外建立全新仓库。不要复制 `.git`，不要沿用旧远端或推送旧分支和标签。提交作者姓名和邮件同样可能公开，应设置愿意公开的署名及平台提供的隐私邮件。

如果资料此前已发布，新的干净仓库不能撤回旧副本。涉及凭证应先撤销或轮换，再依据 [GitHub 敏感数据移除指南](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) 处理历史、缓存、分支和协作者副本。远端可见性、缓存及外部克隆需单独核实。

私有目录仍是本机明文。备份、同步、文件分享及 AI 工具上传都需独立控制。

## 本地 App

App 只绑定 `127.0.0.1`，不提供局域网访问；API 校验 Host、Origin 与每次启动随机生成的内存会话值。页面禁止被嵌入，响应不缓存，不使用 Cookie、浏览器 localStorage、云端字体、遥测或外链预览。应用不记录正文、请求参数、敏感原值或异常堆栈。

数据层只访问 private/workspace 中的 goals、learning、habits、knowledge、journal、reflections。不会自动读取 legacy、memory 或其他私人目录。路径校验拒绝越界、目录联接、符号链接和硬链接记录；界面不允许输入目标路径。

AI 默认未调用。用户选择记录后先查看准确输入快照，明确点击发送后才连接本机 Ollama。固定连接本机端口，不使用系统代理、不跟随重定向、不提供云端降级。拒绝标注 remote_host、remote_model 或 cloud 的模型，并在发送记录前检查本地模型元数据。服务端保存前必须收到确认，正文保留助手草稿标签，不升级为用户事实或修改长期模型。

Ollama 自身及本机操作系统仍是信任边界；App 无法防御恶意替换的本机服务、同账户的恶意进程、磁盘取证或浏览器崩溃转储。请在 Ollama 服务端禁用云端功能，按 [官方 FAQ](https://docs.ollama.com/faq) 配置 OLLAMA_NO_CLOUD 并重启服务。模型下载是用户另行执行的联网操作，App 不自动安装或下载模型。

启动与测试可用 Demo 模式；其中只生成独立虚构记录，在临时工程的 private/workspace 保存，服务正常退出后清理。不要把演示切换为真实资料入口。
